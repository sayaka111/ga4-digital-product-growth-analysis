# 分析方法

## 1. 项目目标

本项目回答一个通用的数字产品增长问题：新增用户是否真正形成核心体验、持续参与、后续转化与可识别价值，以及产品应优先改善哪个环节。

Google Merchandise Store 只是承载该问题的电商场景。分析以业务事件角色而非商品字段组织，因此主体方法可以迁移到游戏、社交、软件服务和内容产品。

## 2. 数据粒度与建模

GA4 原始数据是一条事件一行的嵌套事件流。项目先标准化事件参数和业务角色，再构建相互独立的事实粒度：

```text
GA4 原始事件
    ↓
标准事件层
    ├── 会话事实
    ├── 用户首会话
    ├── 用户日活动
    ├── 用户留存明细
    ├── 用户早期行为特征
    └── 规范订单事实
            ↓
获客、激活、漏斗、留存、生命周期与价值分析集市
```

- 事件层保留时间、来源、设备和业务角色，用于行为顺序与参数解析。
- 会话层汇总一次访问中的参与、阶段到达和首次到达时间。
- 用户层连接首次接触、首会话、早期行为、成熟留存和未来结果。
- 用户日层描述自然日活跃与返回行为。
- 订单层将重复上报与收入识别问题从转化事件中分离。

各实体的正式主键、分母和窗口统一定义在[指标定义](metric_definitions.md)中。

## 3. 分析框架

```text
获客 → 激活 → 参与 → 转化 → 留存 → 生命周期 → 用户价值
```

| 模块 | 回答的问题 |
|---|---|
| 获客 | 哪些首次接触渠道带来足够规模且质量可比较的用户？ |
| 激活 | 用户是否在首次体验中到达核心价值，并在早期重复使用？ |
| 参与 | 用户的使用深度、频率与后续路径如何？ |
| 转化 | 用户在哪个严格有序阶段流失？ |
| 留存 | 用户是否在成熟观察窗口内返回产品或再次完成核心行为？ |
| 生命周期 | 当前用户处于活跃、降温、沉寂或观察未成熟的哪种状态？ |
| 用户价值 | 转化事件能否关联到可识别订单与可确认收入？ |

## 4. 核心分析模块

获客分析把首次接触渠道的规模与后续质量放在同一视图中，并将归因异常与可行动渠道分开。激活分析区分“一次到达核心体验”和“早期重复核心行为”，避免用最终购买代替产品激活。

漏斗分析以会话为单位，只接受可以由事件时间证明的阶段顺序。留存分析同时观察产品返回和核心行为返回，并只比较具备完整观察窗口的用户。早期行为分析将特征窗口与未来结果窗口分开，通过发生率和效应量寻找值得实验验证的候选信号。

最终业务结果见[核心发现](findings.md)，数据可靠性与适用边界见[数据质量与分析限制](data_quality_and_limitations.md)。

## 5. 方法可迁移性

迁移到其他产品时，保留粒度设计、成熟分母、严格顺序、固定结果窗和质量检查，只替换事件角色与结果事实：

| 通用角色 | 当前场景 | 游戏示例 | SaaS 示例 | 社交/内容示例 |
|---|---|---|---|---|
| 首次接触 | `first_visit` | 首次启动 | 注册或首次登录 | 注册或首次访问 |
| 核心价值 | `view_item` | 完成首局或首关 | 创建首个项目 | 关注、观看或深度阅读 |
| 高意向 | `add_to_cart` | 进入付费点 | 邀请成员或试用高级功能 | 收藏、发帖或订阅意向 |
| 转化 | `purchase` | 付费 | 订阅或升级 | 会员或创作者转化 |
| 价值 | 已识别收入 | 付费或长期活跃 | 经常性收入或续订 | 广告、订阅或内容价值 |

迁移时必须重新确认业务价值假设和埋点语义，不能直接照搬当前事件名或金额阈值。
